# Carrel 0.4.0

[Home](../../README.md) · English | [中文](0.4.0.zh-CN.md)

Release pending evaluation; `v0.4.0` has not been tagged yet.

This release connects source-preserving parsing, graph evidence and ontology
review more closely. It adds scoped correction APIs and graph-version
comparison, and moves multimodal parsing to models selected per knowledge base.

## Parsing and evidence

- Preserve code whitespace, line ranges and configuration fields through
  parsing, chunking, graph extraction and source readback. Resolve code imports
  within their project and package scope.
- Improve PDF code recognition, section attribution, short-table recovery and
  row alignment. Recover visible form fields and retain images embedded in
  spreadsheets with their sheet and row locations.
- Pack adjacent short text when section and source boundaries support it.
  Keep code, tables and figures attached to their original evidence regions.
- Retain informative visual content, mark truncated or uncertain model output,
  and preserve original table text when a replacement cannot be aligned.

## Graphs and ontology

- Preserve negated, conditional and uncertain claims with their qualifiers.
  Keep ambiguous identities distinct and constrain relationship endpoints by
  the schema.
- Carry observation dates, units, conditions and source locations into facts
  and cross-document series. Default retrieval retains historical, conflicting
  and future claims; an explicit date filters both facts and change summaries.
- Reuse schema definitions supported by current source evidence, account for
  uncovered document types and retain endpoint-use statistics for review.
  Corpus changes can introduce new types without treating past frequency as
  a permanent constraint.
- Compare graph versions and distinguish changed source material from changed
  extraction output. Keep three graph versions by default and retain schema
  versions referenced by retained builds.
- Add preview, commit and revoke APIs for corrections scoped to library
  identity, graph version and source evidence. Track stale records and preserve
  correction outcomes when a build resumes.

## Retrieval and model configuration

- Share model-parameter compatibility across connectivity checks, graph calls
  and image descriptions. Keep free-form model registration and add scoped
  overrides for custom deployments.
- Improve fused text/image candidate selection, source diversity and bounded
  original-text excerpts. The search skill can navigate documents, locate
  phrases and follow graph evidence with reusable source references.
- Choose one multimodal model from the console registry for each knowledge
  base. Images, charts and table review share it; later parsing tasks use the
  current selection.
- Remove the bundled local VLM container. The optional local-model profile now
  provides four embedding and reranking services. Vision endpoints can run on
  another host or through a compatible provider.
- Complete bilingual progress and error messages, including messages containing
  Chinese model or library names. Document shared and deployment-specific
  [test scope](../testing.md).
- Unify parsing and graph-build stages, actual work counts and waiting states.
  Task details show models, versions and stage records; overall progress is
  marked as an estimate.

## Design

Carrel keeps original evidence, RAG indexes and ontology graphs connected.
Technical checks establish source identity, structural consistency and time
scope. Reviewed corrections capture business interpretation with supporting
evidence. The Agent Loop plugin remains in development and is not implemented.

## Upgrade from 0.3

1. Update the checkout to `v0.4.0` and run `./deploy.sh` with your deployment
   options. The script removes the retired bundled VLM service and its matching
   default configuration; custom vision endpoints are preserved.
2. Register a vision-capable, OpenAI-compatible model in the console and select
   it for each library that uses multimodal parsing. The global `VLM_*` endpoint
   remains available as a default.
3. Restart `carrel-web` and `carrel-search`, or the corresponding application
   processes on other hosts.
4. Plan processing capacity for the parser-profile upgrade. Formats receiving
   the new `+source-v1` profile include PDF, DOCX, PPTX, Markdown, source code
   and notebooks. The next scan requeues indexed files whose recorded profile
   differs. Rows with no recorded profile need an explicit reparse; standalone
   images, XLSX/XLS/CSV/TSV and legacy DOC keep their existing profiles.
5. Reparse selected files to apply improvements that keep the same profile,
   then rebuild enabled graphs to apply the new extraction and evidence rules.
   Graph updates continue to follow each library's incremental/rebuild policy.

Changing the multimodal selection alone does not reparse existing documents.
For a complete refresh, use the console's reparse and graph-build actions.
Clients that previously treated the default graph view as “latest valid fact”
should use explicit time scopes or reviewed governance records for that purpose.
