# Carrel 0.4.4

English | [中文](https://github.com/FengZhenfei/carrel/blob/v0.4.4/docs/releases/0.4.4.zh-CN.md)

Carrel 0.4.4 improves how Light and Standard preserve source material during parsing, chunking and index recovery. Both editions use MinerU 3.4.5 for new deployments.

## Parsing and source evidence

- PDF chunks keep section context when headings sit beside figures or above columns. Local headings inside a diagram have a limited scope so adjacent sections keep their own text.
- Table chunks preserve row and column ownership across merged cells and page breaks. A cell spanning several columns is written once. Tables without a confirmed header identify the covered columns by position. Table review retains source text when it can verify only part of a table.
- Image descriptions retain source captions and footnotes. The parser adapts structured output requests to the model endpoint and reports empty descriptions and simplified retries separately.
- Word footnotes, PowerPoint notes, Markdown, notebooks and source listings retain more of their original structure. Spreadsheet ingestion includes hidden rows, columns and sheets, including their pictures. Sheets marked `veryHidden` stay excluded.
- MinerU caches record the parser version that produced the result. The shared CPU and GPU parser builds install four Noto CJK fonts and render unembedded Japanese and Korean Gothic glyphs during the build.

## Recovery and scheduling

- Index recovery checks which expected chunk IDs are present, including partially restored indexes. Light keyword recovery keeps the collection associated with the recovered document.
- The console distinguishes paused libraries from active parsing. User cancellations survive scheduled scans. After a model configuration change, the scheduler can retry files affected by that configuration.

## Upgrade from 0.4.3

1. Update your deployment checkout to the `v0.4.4` tag. Keep the existing edition, data directories, model mounts and credentials.
2. In `deployment/compose/.env`, set `CARREL_IMAGE=ghcr.io/fengzhenfei/carrel:v0.4.4` and `MINERU_VERSION=3.4.5`. Keep the CPU or GPU settings for your deployment.
3. For a deployment using the integrated MinerU service, rebuild that service from the updated checkout and pull the application image.

```bash
cd deployment/compose
docker compose pull app
docker compose up -d --no-deps --build mineru
docker compose up -d --no-deps --no-build app
```

GHCR publishes the application for Linux amd64 and arm64. The separate MinerU build supplies the new fonts. Existing chunks and graphs keep their previously published content. To apply the parsing changes to existing files, reparse the relevant library and then rebuild its graph if enabled. A library-wide reparse refreshes the MinerU cache as well.
