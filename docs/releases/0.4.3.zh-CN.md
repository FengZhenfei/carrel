# Carrel 0.4.3

[English](https://github.com/FengZhenfei/carrel/blob/v0.4.3/docs/releases/0.4.3.md) | 中文

Carrel 0.4.3 修复 Light 和 Standard 的文档发布、证据一致性、表格解析与恢复问题，增加全文和章节时间上下文，完善检索 Skill 的原文阅读，并将代码语法资源预装到应用镜像。

## 文档发布与证据

- 新版切块在完整发布记录提交后才进入检索。写入失败的内容保持未发布状态，旧数据清理和关键词索引同步单独重试。
- 切块引用绑定正文与文档切块布局，重新解析后，旧事实或引用不会悄然指向另一段文字。文档日期与相应的来源版本匹配。
- Skill 分批回读保持同一文档版本和切块版本，缺失批次会明确报错。不同文档中措辞相同的段落保留各自出处。
- 新增 `kb scan --repair-indexes`，在恢复后检查文档索引是否缺失或不完整，并安排恢复任务。图谱回滚会清除过期页面别名，存储检查失败时保留图谱恢复记录。
- 向量批量响应按索引对应输入，避免向量写到错误切块。已有索引时，阻止直接更换向量端点、模型或维度。

## 解析与图谱抽取

- 表格复核支持空列，并在原文提供唯一对应关系时补回缺失行名，保留已有单元格值；无法确认对齐时，提示具体原因。
- 跨页续表保留原文备注并避免重复占位，PDF 补充原文保留跨字体片段中的短数字、日期和单位。表格切块继续遵守已配置的大小预算。
- 镜像构建时下载并验证支持的代码语法资源，包括 Markdown、HTML 辅助资源，首次解析时无需再下载。
- 本体提示词按领域基数定义单值关系，保留有分歧的来源声明供复核。

## 时间上下文与检索

- 建图可引用全文或章节明确声明的时间范围，保留支持该时间的原文和来源版本。片段中的明确日期优先，章节时间只在对应范围内使用。
- 区分统计期、实验期和事实有效期。完整期间的汇总结果按期间结束时间定位，实验结束后仍可查询历史测量；财年边界依据原文明确给出的对应关系。
- 时间上下文无法与某条事实确认关联时，该事实时间保持未知，不用文档日期填补。默认查询和历史查询保留这些记录，明确指定 `as-of` 时将其排除；较晚发表的文档仍可作为早期事件的证据。
- 检索保留时间出处，Skill 区分文档日期、观察时间和未确认时间，回读原文时保留上级章节标题。

## 检索 Skill 与访问控制

- `show --sources` 集中阅读原文；`context --opening` 回读同版本文档开头。编号追问选项只包含相关且正文尚未回答的线索。
- 图文混合查询中，视觉评分偏低时仍保留已通过文本门槛的证据。
- 控制台鉴权覆盖反向代理子路径，检索接口先鉴权再解析请求体，模型及解析服务请求拒绝重定向。
- Skill 缓存使用私有目录和文件权限，生成配置正确处理 shell 特殊字符，并更新依赖锁定版本。

## 升级

使用仓库标签 `v0.4.3` 和应用镜像 `ghcr.io/fengzhenfei/carrel:v0.4.3`（Linux amd64、arm64）。已有 Compose 部署在 `deployment/compose/.env` 中设置 `CARREL_IMAGE`，然后执行：

```bash
cd deployment/compose
docker compose pull app
docker compose up -d --no-build app
```

同时更新智能体中安装的 `carrel-search` Skill。

已有知识库应重新解析文档，再重建已启用的图谱，使数据完整采用新的证据标识和解析修复。保留原始文件和模型配置。控制台的**整库重新解析**会刷新解析缓存，包括 MinerU 输出；普通重试和缺失索引恢复可以复用匹配的 MinerU 缓存。仅更新应用镜像不会改写已有切块和图谱。

已经采用 0.4.3 解析和证据修复的知识库，只需重建图谱即可应用新增的时间上下文抽取，已有切块和 MinerU 缓存可以保留。
