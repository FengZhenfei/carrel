# Carrel 0.4.4

[English](https://github.com/FengZhenfei/carrel/blob/v0.4.4/docs/releases/0.4.4.md) | 中文

Carrel 0.4.4 改进了 Light 和 Standard 在解析、切块和索引恢复时保留原文证据的方式。两个版本新部署时均默认使用 MinerU 3.4.5。

## 解析与原文证据

- PDF 标题位于图片旁或分栏上方时，切块会保留其章节上下文。图内标题的作用范围限制在相应区域，减少相邻章节正文错挂的问题。
- 表格切块保留合并单元格及跨页续表的行列归属。横跨多列的正文只写一次，无法确认表头时按位置标注适用列。表格复核只能确认部分内容时，仍保留未确认部分的原文。
- 图片描述保留来源图注和脚注。解析器会按照模型端点支持的格式请求结构化输出，并分别提示图片无描述和简化重试。
- 改进 Word 脚注、PowerPoint 备注、Markdown、Notebook 和代码清单的结构保留。电子表格会读取隐藏行、列、工作表及其中的图片，标为“非常隐藏”（`veryHidden`）的工作表仍排除。
- MinerU 缓存记录生成结果的解析器版本。CPU 和 GPU 解析镜像均安装四款 Noto CJK 字体，构建时实际渲染未内嵌字体的日文和韩文黑体字形。

## 恢复与调度

- 恢复索引时逐项检查预期切块 ID，能识别仅恢复部分切块的情况。Light 恢复关键词索引时会保留文档所属的集合。
- 控制台区分已暂停的知识库和正在解析的任务。定时扫描保留用户的取消操作。修改模型配置后，调度器可以重试受该配置影响的失败文件。

## 从 0.4.3 升级

1. 将部署使用的仓库更新到 `v0.4.4` 标签，保留原有版本选择、数据目录、模型挂载和凭据。
2. 在 `deployment/compose/.env` 中设置 `CARREL_IMAGE=ghcr.io/fengzhenfei/carrel:v0.4.4` 和 `MINERU_VERSION=3.4.5`，沿用本机的 CPU 或 GPU 设置。
3. 如果使用集成的 MinerU 服务，从更新后的仓库重建该服务，并拉取应用镜像。

```bash
cd deployment/compose
docker compose pull app
docker compose up -d --no-deps --build mineru
docker compose up -d --no-deps --no-build app
```

GHCR 提供 Linux amd64 和 arm64 应用镜像，新增字体随单独构建的 MinerU 镜像交付。已有切块和图谱保留已发布内容。如需让已有文件采用新的解析逻辑，可对相应知识库执行整库重新解析，完成后再重建已启用的图谱。整库重新解析也会刷新 MinerU 缓存。
