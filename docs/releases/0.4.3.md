# Carrel 0.4.3

English | [中文](https://github.com/FengZhenfei/carrel/blob/v0.4.3/docs/releases/0.4.3.zh-CN.md)

Carrel 0.4.3 fixes document publication, evidence consistency, table parsing and
recovery in both Light and Standard. It also improves source reading in the search
Skill and includes code grammar libraries in the application image.

## Document publication and evidence

- New document chunks become searchable after their complete publication record
  is committed. Failed writes remain unpublished; cleanup and keyword-index
  synchronization retry separately from parsing.
- Chunk references bind to their text and document layout. Reparsing cannot
  silently redirect an old fact or citation to a different passage. Document dates
  are matched to the corresponding source version.
- Paginated Skill reads retain the same document and chunk revision and report
  incomplete batches. Identical passages from different documents retain their
  independent sources.
- `kb scan --repair-indexes` detects missing or incomplete document indexes after
  a restore and queues recovery. Graph rollback clears obsolete page aliases;
  failed storage checks retain graph recovery records.
- Embedding batches follow response indices, preserving the mapping from each
  input to its vector. Changing an embedding endpoint, model or dimension is
  blocked while existing indexes use the previous configuration.

## Parsing and graph extraction

- Table review handles empty columns and recovers missing row labels when the
  source provides an unambiguous match. It preserves existing cell values and
  reports more specific reasons when alignment cannot be confirmed.
- Cross-page table continuation handling preserves source notes and avoids
  duplicate placeholders. Supplementary PDF text retains short numbers, dates and
  units across font spans. Table chunks continue to use the configured size budget.
- Supported code grammars, including Markdown and HTML helpers, are downloaded
  and load-checked during the image build, so parsing does not fetch them on first use.
- The ontology prompt defines single-valued relations by domain cardinality and
  keeps competing source claims for review.

## Search Skill and access controls

- `show --sources` presents original passages together; `context --opening` reads
  the opening of the same document version. Numbered follow-up choices cover
  relevant leads that the answer has not already addressed.
- Mixed text/image queries retain accepted text evidence when visual scores are low.
- Console authentication covers reverse-proxy subpaths. Search authenticates before
  parsing request bodies, and model/parser requests reject redirects.
- Skill caches use private directories and files. Generated configuration handles
  shell-special characters, and dependency pins are updated.

## Upgrade

Use the `v0.4.3` repository tag and application image
`ghcr.io/fengzhenfei/carrel:v0.4.3` (Linux amd64 and arm64). In an existing Compose
deployment, set `CARREL_IMAGE` in `deployment/compose/.env`, then run:

```bash
cd deployment/compose
docker compose pull app
docker compose up -d --no-build app
```

Refresh the bundled `carrel-search` Skill in your agent as well.

For existing libraries, reparse their documents and then rebuild enabled graphs
to apply the new evidence identifiers and parsing repairs throughout the data.
Keep source files and model configuration. The console's **Reparse entire library**
action refreshes parse caches, including MinerU output. Ordinary retries and the
missing-index recovery workflow can reuse matching MinerU caches; updating the
application image alone does not rewrite existing chunks or graphs.
