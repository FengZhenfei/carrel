# Carrel 0.4.0

[首页](../../README.zh-CN.md) · [English](0.4.0.md) | 中文

本次更新进一步连接原文保真、图谱证据和本体审定，新增限定证据范围的更正接口与图谱版本比较，并将多模态解析改为按知识库选择模型。

## 解析与证据

- 保留代码空白、行范围和配置字段，贯通解析、切块、图谱抽取与原文回读；代码导入关系按项目和包的范围解析。
- 改善 PDF 代码识别、章节归属、短表格恢复和行对齐；读取可见表单字段，保留电子表格中的图片及工作表、行定位。
- 在章节和来源边界允许时合并相邻短文本；代码、表格和图片继续关联各自的原文区域。
- 保留有信息的视觉内容，标记模型输出截断与不确定性；替换结果无法对齐时保留原始表格文本。

## 图谱与本体

- 为否定、条件和不确定声明保留限定信息；区分身份不明确的实体，按照模式约束关系端点。
- 将观察日期、单位、条件和原文位置传入事实及跨文档序列。默认检索保留历史、冲突和未来声明；指定日期时同时筛选事实和变化摘要。
- 复用仍有当前来源支持的模式定义，补充未覆盖文档类型，并记录端点使用情况供审查。语料变化可以引入新类型，历史频率不再成为永久约束。
- 对比图谱版本，区分原文变化与抽取输出变化。默认保留三个图谱版本，同时保留这些构建引用的模式版本。
- 新增更正预览、提交和撤销接口，按知识库身份、图谱版本及来源证据限定范围；追踪失效记录，续跑建图时保留已应用结果。

## 检索与模型配置

- 连通性检查、图谱调用和图片描述共用模型参数兼容规则；保留自由配置模型的方式，并支持按部署覆盖参数。
- 改善图文融合候选、来源多样性和限定长度的原文摘录。检索 Skill 可定位文档、查找短语，并通过可复用的来源引用继续追查图谱证据。
- 每个知识库从控制台模型列表选择一个多模态模型，图片、图表理解与表格复核共用该模型，后续解析任务读取当前选择。
- 移除内置本地 VLM 容器，可选本地模型组合保留四个向量与重排服务。视觉接口可以部署在其他主机，也可使用兼容的服务商接口。
- 补齐进度和错误消息的中英文显示，包括含中文模型名、库名的消息，并明确通用与部署专项的[测试适用范围](../testing.zh-CN.md)。
- 统一解析与建图的阶段、实际处理计数和等待状态；任务详情展示模型、版本与阶段记录，总体进度标为估算。

## 设计考量

Carrel 将原文证据、RAG 索引和本体图谱连接起来，通过技术校验建立来源身份、结构一致性和时间范围，再由审定更正承载有证据支持的业务解释。Agent Loop 插件仍在开发中，尚未实现。

## 从 0.3 升级

1. 将代码更新到 `v0.4.0`，按原部署选项运行 `./deploy.sh`。脚本会移除退役的内置 VLM 服务及其对应默认配置，自定义视觉接口继续保留。
2. 在控制台注册支持图片输入的 OpenAI 兼容模型，为需要多模态解析的知识库选择它；也可继续用全局 `VLM_*` 接口作为默认值。
3. 重启 `carrel-web` 和 `carrel-search`；其他环境重启对应应用进程。
4. 为解析档案升级安排处理容量。PDF、DOCX、PPTX、Markdown、源代码、Notebook 等格式新增 `+source-v1` 档案；已入库文件记录的档案与当前不一致时，下次扫描会重新排队。没有记录旧档案的行需要手动重新解析；独立图片、XLSX/XLS/CSV/TSV 和旧版 DOC 保持原档案。
5. 对需要应用同档案解析改进的文件执行重新解析，再重建已启用的图谱以应用新的抽取和证据规则。日常图谱更新继续遵循各库的增量及重建策略。

仅更换多模态模型不会自动重新解析历史文档。需要完整刷新时，使用控制台的重新解析与建图操作。此前将默认图谱视图视为“最新有效事实”的调用方，应通过明确的时间范围或审定治理记录表达这一需求。
