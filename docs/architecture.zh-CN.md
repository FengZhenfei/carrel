# 架构说明

[首页](../README.zh-CN.md) · [English](architecture.md) | 中文

Carrel 将入库、建图和检索分为独立流程，通过 SQLite 记录文件、配置、任务和构建进度。控制台负责管理这些流程，智能体通过检索 API 获取证据。

## 入库流程

1. **扫描已启用目录。** 根据元数据和内容校验和判断变化，暂缓处理新近写入的文件，为新增或变化内容排队。删除操作进入索引生命周期管理，详见 [资料目录规则](configuration.zh-CN.md#资料目录)。
2. **按格式解析。** PDF、DOCX 和 PPTX 使用 MinerU 集成；表格使用原生读取器；HTML、Markdown 保留文档结构；代码围绕符号切块。独立的视觉语言模型负责插图、图片文件及 XLSX 内嵌图片的描述，包括普通锚定图片和 WPS 单元格图片，并保留工作表与单元格位置。
3. **生成切块。** 先合并适合合并的正文、列表和跨页表格，再按 token 限制拆分，保留文档位置、章节路径、表头，以及可用的页码、幻灯片或行号信息。
4. **生成向量并写入索引。** 文本向量输入包含文档与章节上下文。Qdrant 存储文本向量和可选的视觉向量，OpenSearch 用内置的 `cjk` 分析器索引切块文本，两字中文词可以直接命中；原文保留在数据载荷中。
5. **维护处理状态。** 解析器版本用于判断是否需要重处理。任务租约、重试、取消检查和缓存支持中断恢复，任务连不上所需的服务时退回队列等待，不计入失败次数；旧内容版本失活后，由维护任务按策略清理。

MinerU 容器按部署环境选择解析后端，GPU 与 CPU 路径有所不同。应用使用 `MINERU_BACKEND=auto` 时读取容器的选择结果，详见 [解析容器说明](../deployment/compose/README.md#the-parser-container)。

还支持 R、Jupyter Notebook、RST、Quarto/RMarkdown、TeX、BibTeX、JSONL、TSV、Nextflow/CWL/WDL、Snakefile、Feature、DOT、XSD 和日志。Notebook 保留单元格编号、代码、已保存的文本/表格输出及位图；JSONL 保留记录行号，TSV 保留列与行范围。脚本和文档模板采用静态读取。Markdown 正文中过滤 HTML 注释，代码示例保持完整。扫描时忽略 Git LFS 占位文件，不计入文件清单或解析队列；已入库文件变为占位符时撤下旧索引，补回原件后按正常增量流程入库。

代码文件和文档内的代码示例切分时保留空格和字面文本，换行统一为 LF。代码文件保留行列范围，内嵌示例保留其在解析块中的位置，文档中的代码图注单独保留。解析版本记录提取与切块规则的变化，后续扫描可据此重新处理受影响文档。

每个知识库可从模型列表选择一个**多模态模型**，统一用于图片、图表理解和基于截图的表格复核，支持部署在其他机器上的 OpenAI 兼容视觉接口。选择**系统默认**时使用 `VLM_*` 配置。保存选择后用于后续解析，已有文档在显式重新解析前保留当前结果。

PDF 解析同时读取可见表单字段，将局部文字、图注和图例关联到各自来源区域。表格缺少原生文字时进行局部视觉复核，替换前校验行身份、已有数值、单位和条件；行列对应仍不明确时保留原表，并单独标注补充的原文。

图片理解结合来源上下文，替换未经确认的上游模型转录。视觉事实按完整语句切分，保留来源定位，同一张图仍只生成一个视觉向量。模型输出截断时保留完整事实并记录质量提示。标题归属与跨页续表结合章节和版面判断。

装饰判定作为描述信息保留，图片不因尺寸、文件名或该判定而丢失。去重作用于模型生成的重复事实；源文件中的文字、重复行与代码原样保留。Word 原生结构没有分页位置时，以章节定位内容。

## 知识图谱构建

每个知识库可单独启用图谱。实体类型和关系从资料样本中自动归纳。

| 阶段 | 处理内容 |
|---|---|
| 类型与关系准备 | 生成版本化的 LinkML 模式，包含八类上层类型、类型继承、身份范围和关系定义 |
| 抽取 | 将连续切块组成抽取单元，提取带来源的实体、关系和结构化事实 |
| 确定性处理 | 直接抽取代码和配置结构；先归纳表格列的角色，再按行生成实体和带条件的事实 |
| 归并与核对 | 归一实体与属性概念、规范单位，保留冲突证据和时间信息 |
| 派生视图 | 根据已有事实与关系编译主体页、时间线页和来源页 |
| 发布 | 写入版本化的 Qdrant 图证据集合，并按配置导入 Neo4j；通过失败检查与回滚机制协调版本生效 |

抽取响应按输入和配置指纹缓存。增量构建复用未变化的抽取结果、归并决策和向量，已删除文档会从后续图版本移除；达到时间或变化阈值时，可改为整库重建，默认先重新抽取标签。全局构建锁协调各库的图谱构建，同一时间运行一个。

模式演进保留仍有当前原文支持的定义，同时接纳新增主题。每轮归纳提出精简的候选类型和关系，保留的旧定义不占用本轮候选名额。既有含义、方向和基数保持稳定；关系端点的增补需要具名、具类型的两端及可核对的原文引句，使用频次本身不扩大约束。随着资料主题逐步变化，模式可以扩展，仍有依据的旧类别也继续可解释。

配置事实保留完整字段值，并定位到实际包含该字段的原文切块。事实归一保留标识符、量值、明确主体和条件；有歧义的缩写保持分开，代码导入按项目和包的范围解析。证据位置贯穿两种图谱存储与检索返回。

合并的代码切块按源码位置保留内部符号；原生表格的重叠行共享同一来源单元格的事实，并保留全部证据引用。密集表格按抽取预算分批处理，每批带上列名上下文。根据名称推导的候选关系保留供审查，不参与图遍历。

建图工作文件位于 `runtime/graph/`，构建锁用于协调图谱进程。关系和编译页面保留来源引用，智能体可据此获取对应原文。

八类上层类型为 `agent`、`entity`、`part`、`property`、`process`、`event`、`concept`、`document`。实体区分类与实例，保留原文中的外部标识和来源引用；每库更正文件提供可复用的身份和文档状态规则。现行与历史视图保留被取代的证据。

Carrel 提供通用知识存储、检索和证据接口。**Agent Loop 插件目前开发中，尚未实现**；其目标是使用这些接口学习企业本体、向相关人员求证，并维护更正规则。

## 检索流程

查询链路使用向量与打分模型，答案生成由调用方智能体完成。

1. 在各库中探测向量与关键词证据；调用方明确指定 `kbs` 时按指定范围检索。图片查询还可引入视觉证据。
2. 按证据分数选择知识库；选中的库没有可用结果时，自动路由可以扩大检索范围。
3. 在具备相应能力的知识库中补充图谱和视觉候选。
4. 通过倒数排名融合（RRF）合并候选，兼顾多个主体或文档，并按配置并行执行文本和图片重排；两路独立判断相关性后按名次融合，缺失的图片评分回退文本。
5. 按覆盖度和多样性选择结果，拼接邻近切块与表格续片，去除可确认的重叠，并分配文本 token 预算。
6. 返回证据、来源位置与诊断状态。

路由结合向量相似度和跨库加权的词法证据。排序与路由参数可以配置，实际数值由部署环境决定；Python 回退值位于 [`kb_search/config.py`](../app/kb_search/config.py)。

API 提供图邻域查询，供智能体按问题逐步追查关系。关系结果包含来源引用，并受查询范围和返回数量限制。结果状态、来源核验、过滤与补查方式见 [检索与 API](retrieval.zh-CN.md)。

## 服务分工

| 组件 | 职责 |
|---|---|
| SQLite | 文件登记、配置、队列、切块和建图状态 |
| MinerU 与原生解析器 | 提取文档结构与内容 |
| 模型接口 | 文本/视觉向量、图片描述、图谱抽取和可选重排 |
| Qdrant | 切块向量与版本化的图证据集合 |
| OpenSearch | 关键词索引 |
| Neo4j | 图谱投影与关系查询 |
| Web 控制台，端口 9800 | 知识库配置和运行管理 |
| 检索 API，端口 9810 | 为智能体提供证据 |

两个应用服务运行在提供的 Compose 容器栈之外。Linux 上由用户级 systemd 服务和定时器驱动控制台、检索、入库、图更新与维护，详见 [运维说明](operations.zh-CN.md)。

## 代码结构

```text
app/
  kb_pipeline/        入库、建图、命令行和维护
    pipeline/         扫描、调度、worker 和解析任务
    parsers/          格式路由与文档解析
    chunking/         切块组装和诊断
    embedding/        文本与视觉向量客户端
    graph/            类型归纳、抽取、归并、事实与发布
    vector/           Qdrant 结构与写入
    vision/           图像处理与描述
    localfs/          本地资料扫描
  kb_server/          控制台 API、业务逻辑与静态前端
  kb_search/          路由、召回、排序与证据组装
  tests/              回归测试与共用夹具
config/               应用环境配置模板
deployment/           Docker Compose 文件与 systemd 模板
scripts/              部署与定时任务辅助脚本
skills/carrel-search/ 智能体 Skill 与仅依赖标准库的 Python 客户端
docs/                 配置、架构、API 和运维文档
deploy.sh             部署入口
```

运行产物保存在 Git 忽略的目录。`runtime/` 下有镜像资料（`mirror/`）、状态库（`state/kb-pipeline.db`）、解析缓存（`parse_cache/`）、建图工作区和 LLM 响应缓存（`graph/work/<base>/<version>/`、`graph/cache/<base>.sqlite`）、建图锁（`state/graph_build.lock.d/`）以及各存储服务的数据（`qdrant_data/`、`opensearch/`、`neo4j/`）；`models/` 存放权重，`logs/` 与 `backups/` 存放运行文件。

## 定点纠正

每个库在 `config/corrections/<kb_id>.yaml` 中拥有独立身份标识；编号复用时新库获得新身份。纠正记录关联审定时的图谱版本、来源单元和模式指纹，依据变化后标记待复核。记录在下一次建图时应用，支持撤销，原文切块保留。

| 控制台 API | 用途 |
|---|---|
| `GET /api/kbs/{kb_id}/corrections` | 库身份、文件修订号、记录及上次建图执行结果 |
| `POST /api/kbs/{kb_id}/corrections/preview` | 定位目标并校验依据，不写入 |
| `POST /api/kbs/{kb_id}/corrections` | 提交记录 |
| `POST /api/kbs/{kb_id}/corrections/{id}/revoke` | 撤销，附 `submitted_by` 和 `reason` |
| `GET /api/kbs/{kb_id}/graph_comparisons` | 列出版本对比；`?version=...` 获取详情 |

提交字段为 `id`、`action`、`targets`、`base_graph_version`、`library_identity`、`revision`、`submitted_by` 和 `evidence`。动作支持 `entity.type`、`entity.aliases`、`entity.merge`、`entity.separate`、`entity.reject`、`relation.reject` 和 `fact.reject`；类型和别名变更另带 `value`。目标可按实体键、外部标识、文档／单元、作用域、事实属性、值、条件和时间精确定位；每个选择器必须唯一命中。同一记录编号和内容重复提交不重复写入，并发修改校验 `revision`。

Carrel 负责记录和执行纠正，业务解释和依据由人及后续 Agent Loop 提供。
